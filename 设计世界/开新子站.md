# 开一个新子站

从「有个想法」到「上线」的完整流程。每一步都写了你要说什么、Claude 会做什么。

## 第 1 步　想清楚它是什么（5 分钟，你来）

写给自己三句话：

- 它是什么（一个游戏？一套题？一个工具？）；
- 访客来这里做什么；
- 主要在手机上用，还是在电脑上用。

如果有喜欢的参考图或关键词，也准备好。这一步是可选的。

## 第 2 步　选世界：`/new-world`

开一个新会话，输入：

```
/new-world 子站名 关键词（可选）
```

参考图直接拖进对话框。这个命令只有你手动输入才会触发，Claude 不会自己调用它。

Claude 会依次做这些事：

1. 读现有的所有 DESIGN.md 和 `设计世界/弃稿.md`，列出这次要避开的东西。
2. 提出 5 个方向。每个方向都取材于一个具体的现实物件，并且彼此不同领域。
3. 每个方向做一屏静态样张，截图发给你，附一张总览图。

**你要做的：从 5 个里选 1 个。**

- 想微调，就说「选 3，但颜色再暗一点」。它会在样张上改一轮再给你看。
- 都不喜欢，就说「都不要」。这 5 个会记进弃稿，它再提 5 个新的。

你选定之后，Claude 会做三件事：

- 在子站的源码目录写好 DESIGN.md，比如 `src/<代号>/DESIGN.md`；
- 把选中的样张存进 `设计世界/定稿/<代号>/`；
- 把没选的方向记进 `设计世界/弃稿.md`，以后不会再提。

## 第 3 步　搭架子（跟 Claude 说一句就行）

> 按 `src/<代号>/DESIGN.md` 和 `设计世界/定稿/<代号>/` 的样张，开始做〈子站名〉，先把页面入口和小镇里的门搭好。

这一步通常包括下面几件事。Claude 会做，你知道有这些就行：

- **页面入口**：`<代号>/index.html`，源码放在 `src/<代号>/`。还要在 `vite.config.js` 的 `input` 里加一行，不然它不会被打包上线。
- **小镇里的门**：在 `src/pages.js` 对应那栋楼的 `cards` 里加一张卡片，写上 `href` 和 `ready: true`。
- **门口的桥**：
  - 卡片的特写镜头（`spot`）；
  - 登机牌：存根用新世界的风格来印；
  - 起飞转场（`takeoff`）：从小镇进入新世界的那一下。

  这几样是小镇和新世界之间唯一的连接，可以等页面做好以后再细做。

## 第 4 步　做页面、改设计（反复来回）

- **直接提需求。** 改这个子站的文件时，impeccable 会自动读这个子站自己的 DESIGN.md，不会被拉回小镇的风格。
- **觉得不对劲但说不清哪里不对。** 先让它出一份问题清单，你挑要改的：

  ```
  /impeccable critique 〈子站名〉首页
  ```

- **定向改。** 用下面这些命令，比只说「更有设计感」管用得多：
  - `/impeccable bolder 〈对象〉`：更大胆
  - `/impeccable quieter 〈对象〉`：收一收
  - `/impeccable typeset 〈对象〉`：调字体和排版
  - `/impeccable layout 〈对象〉`：调布局
  - `/impeccable colorize 〈对象〉`：调颜色
  - `/impeccable polish 〈对象〉`：上线前打磨
- **上线前做一次体检**，查无障碍、性能和手机适配：

  ```
  /impeccable audit 〈对象〉
  ```

- **同一条意见说到第三次，** 就说「把这条写进这个子站的 DESIGN.md」。以后就不用再说了。

## 第 5 步　收尾和上线

1. 代码基本定型后，跑一次：

   ```
   /impeccable document
   ```

   它会把 DESIGN.md 从「样张版」刷新成「真实代码版」。它问你刷新还是合并时，选「合并」，这样你手写进去的规矩会保留下来。
2. 提交并推送到 `main`。GitHub Pages 会自动发布。

## 小提示

- 想回看以前否掉的方向，看 `设计世界/弃稿.md`。样张截图只在这台电脑上，路径在每一条记录里。
- 如果哪天觉得某个子站该整个换风格，也可以对它重新跑 `/new-world`。现有的世界会进禁区清单，新方向不会和它撞。
- 这些文件管什么：
  - 根目录的 `DESIGN.md` 只管小镇。
  - 每个子站的 DESIGN.md 只管它自己。
  - `PRODUCT.md` 管全站的产品事实（给谁、做什么、有哪些约束），各个子站共用。
